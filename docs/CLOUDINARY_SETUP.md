# Cloudinary image storage setup

This project uses Cloudinary for profile photos, lost/found report images, and chat attachments.

Firebase is still used for:

- Authentication
- Cloud Firestore user profiles
- Cloud Firestore lost/found reports

Cloudinary is used for:

- Profile-photo uploads
- Report-photo uploads
- Public HTTPS image delivery URLs stored in Firestore
- Chat photos, short videos, and files up to the app's 20 MB limit

## Why Cloudinary

Firebase Storage requires a Firebase billing upgrade before the default Storage bucket can be created. If Firebase is refusing to validate your card, Cloudinary lets the app keep image uploads working without depending on Firebase Storage tonight.

## 1. Create a Cloudinary account

1. Go to [Cloudinary](https://cloudinary.com/).
2. Create or sign in to your account.
3. Open the Cloudinary Console dashboard.
4. Copy your `cloud name`.

Do not copy the API secret into this Android app. Mobile apps can be decompiled, so secrets in app code are not secret.

If a Cloudinary API secret has been pasted into a chat, screenshot, repository, terminal log, or shared document, rotate/regenerate it in Cloudinary. The app does not need the API key or API secret for the unsigned-upload approach.

## 2. Create an unsigned upload preset

1. Open Cloudinary Console.
2. Go to Settings.
3. Open Upload.
4. Open Upload presets.
5. Click Add upload preset.
6. Set Signing Mode to Unsigned.
7. Name it something simple, for example:

   ```text
   cbu_find_unsigned
   ```

8. Recommended preset restrictions:
   - Resource types: Image, video, and raw files (chat uses Cloudinary's `auto` endpoint)
   - Folder: `cbu-find`
   - Allowed formats: restrict these to the image, video, and document formats your campus accepts
   - Maximum file size: keep it small if available in your plan/settings

The app compresses report/profile images to JPEG under 5 MB. Chat attachments are not recompressed and are rejected above 20 MB; set a matching or lower maximum in Cloudinary for defense in depth.

## 3. Add Cloudinary values locally

Open `local.properties` in the project root and add:

```properties
CLOUDINARY_CLOUD_NAME=your_cloud_name_here
CLOUDINARY_UPLOAD_PRESET=cbu_find_unsigned
```

Then rebuild the app. These values become Android `BuildConfig` fields at build time.

For the web client, copy `web/.env.example` to `web/.env.local` and set:

```properties
NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME=your_cloud_name_here
NEXT_PUBLIC_CLOUDINARY_UPLOAD_PRESET=cbu_find_unsigned
```

Do not add `CLOUDINARY_API_SECRET`, `API_SECRET`, or similar values to this Android project.

## 4. Verify in the app

1. Sign in.
2. Open profile.
3. Choose a profile photo and save.
4. Create a report with one to three photos.
5. Confirm the report appears on the home screen with image previews.
6. Confirm Cloudinary Media Library shows the uploaded images.
7. Open Messages, attach a photo or small file, and confirm it appears in the same conversation on web and Android.

## Security notes

- This app uses unsigned uploads because there is no trusted backend function yet.
- Never place Cloudinary API secret in Android code, Firestore, or `local.properties` if the file may be shared.
- For a production campus-wide app, replace unsigned uploads with signed uploads generated by a trusted backend.
- Unsigned presets should be tightly restricted and monitored. For production, route uploads through a trusted backend that issues short-lived signed upload parameters.
